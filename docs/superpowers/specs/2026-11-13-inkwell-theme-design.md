# Inkwell：Hugo 阅读主题设计文档

日期：2026-11-13
状态：待批准

标注说明：没有标注的内容是使用者在讨论中明确定下的；标有 **［我的决定］** 的是设计者补上的默认值，使用者没有逐条讨论过，可以推翻；“留给实现者”一节列出的内容由实现者自行判断。

## 1. 意图

做一个以“读文章”为中心的 Hugo 主题，名为 Inkwell（**［我的决定］** 沿用仓库名）。使用者关注三件事：

1. 简约，不堆功能和装饰。
2. 窄屏（手机）和宽屏（桌面）都有认真设计过的阅读体验，而不只是“能看”。
3. Markdown 正文渲染好看，并且文章有目录。

内容以中文为主，夹少量英文和代码。四类内容都要照顾到：技术文章（代码多）、长篇文字、图文、系列文档。

主题是独立可复用的：这个仓库就是主题本身，别人克隆下来、复制一小段站点配置（见 5.9）就能用。

## 2. 目标、非目标、反目标

### 目标

- 文章页在三档宽度下各有合适的布局，目录始终够得着。
- 中文长文读起来舒服：行宽、行高、段距、中英混排、标点都按中文调过。
- 代码块、表格、图片、公式、图表、提示框都有成体系的样式，明暗两套都好看。
- 使用者只需要 `hugo` 一个命令，没有 Node，没有额外构建步骤。
- 带一个 `exampleSite`，既是演示，也是覆盖所有样式的验收样本。

### 非目标（明确不做）

- 多作者、作者页。
- 社交分享按钮、统计、广告位。
- 封面大图、轮播、卡片瀑布流。
- 多语言站点的语言切换界面（界面文字本身提供中英两套，见 5.9）。
- 复杂的主题定制系统（只开放少量配置项和 CSS 变量）。

### 反目标（出现就算失败）

- 手机上任何内容把页面撑出横向滚动条（超宽的代码、表格、图片、公式、长链接都必须自己处理）。
- 深色模式加载时先闪一下白色。
- 需要 npm、打包器或构建后脚本才能用。
- 关掉 JavaScript 后文章读不了。
- 为了“功能全”让页面变花：新增任何常驻界面元素都要有充分理由。

## 3. 约束

- Hugo 最低版本 **0.146.0**（**［我的决定］**：这是新版模板目录结构的起点；使用者同意“要求较新版本”，具体数字由我定）。开发与验收用 brew 当前稳定版 0.169.0，本机现为 0.124.1，实现前需升级（使用者已同意）。
- 需要 Hugo extended 吗：不需要。只用纯 CSS，不用 Sass。
- 不引入 npm 依赖。第三方库只有三个，全部按需从 CDN 加载、地址可配置：KaTeX 样式（公式）、Mermaid（图表）、giscus（评论）。
- 只用系统字体，不加载网络字体。
- Hugo 只会合并主题配置里的 `params`、菜单、输出格式和媒体类型，**不会**合并 `taxonomies`、`markup`、`outputs`、语言等设置。所以主题无法替使用者声明“系列”分类法、公式定界符等，处理方式见 5.9。
- 浏览器：近两年的 Chrome、Safari、Firefox、Edge 及对应移动版。新 CSS 特性可以用，但必须是渐进增强，不支持时不能坏。

## 4. 考虑过的实现方案

| 方案 | 做法 | 取舍 |
|---|---|---|
| 一、纯 Hugo（**已选**） | 手写 CSS + 原生 JS，Hugo 资源管道合并压缩；搜索用 Hugo 输出的 JSON 索引加自写匹配脚本 | 使用门槛最低；搜索只是关键词包含匹配，上千篇时索引偏大 |
| 二、纯 Hugo + Pagefind | 同上，搜索换 Pagefind | 中文分词和大站点表现更好；但构建后要多跑一步，本地预览默认搜不了 |
| 三、Tailwind + npm | 用 Tailwind 写样式 | 开发快；但使用者必须装 Node，样式也更难覆盖，和“简约可复用”相悖 |

使用者选了方案一。理由：个人博客和文档站一般到不了搜索吃力的规模，“装上就能用”更重要。搜索要做成独立模块，将来换 Pagefind 时只动这一块。

## 5. 设计

### 5.1 视觉风格：素白

使用者在三个方向（纸墨 / 素白 / 墨线）里选了素白：

- 浅色：纯白背景，近黑正文（约 `#1f2328`），灰色次要文字，蓝色链接与强调色（约 `#1f6feb`），浅灰代码块背景（约 `#f6f8fa`）。
- 字体：系统黑体。中文回退顺序 **［我的决定］**：`-apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`；等宽 `ui-monospace, "SF Mono", Menlo, Consolas, monospace`。
- 标题加粗但不夸张，层级靠字号和间距区分，不靠颜色和装饰线。
- 圆角小而统一，边线细而浅，不用阴影（抽屉和弹窗除外）。
- 深色 **［我的决定］**：从浅色推导，深灰背景而非纯黑（约 `#0d1117` 一档），正文为柔和的浅灰白，强调色换成更亮的蓝，代码块比页面背景略亮。
- 所有颜色、字号、间距都定义为 CSS 变量，使用者可以在自己的站点里覆盖。

### 5.2 文章页布局（三档宽度）

| 宽度 | 系列文章 | 非系列文章 |
|---|---|---|
| 大屏 | 三栏：左“系列篇目”，中正文，右“本文目录” | 正文居中，右侧“本文目录” |
| 中等（横屏平板、小笔记本，约 1024 一档）**［我的决定］** | 正文 + 右侧目录；左栏收起，系列篇目通过悬浮按钮的抽屉查看 | 正文 + 右侧目录 |
| 窄屏（手机、竖屏平板，含 768） | 单栏；右下角悬浮按钮，点开底部抽屉 | 同左 |

细则：

- 正文栏宽度固定为每行约 40 个汉字 **［我的决定］**，不随屏幕变宽，任何一档都不为了塞侧栏而挤窄正文。
- 居中规则 **［我的决定］**：大屏用对称的三列网格，正文在视口正中（非系列文章左列留空）；中等宽度放不下对称布局，改为“正文 + 右侧目录”作为一个整体居中，正文略偏左；窄屏单栏居中。放不下“完整正文 + 可用目录”的宽度一律按窄屏处理。
- 左右侧栏吸附在视口内随页面滚动，内容过长时侧栏自己滚动。
- 右侧目录随阅读位置高亮当前章节；左侧系列篇目高亮当前文章。
- 断点的具体像素值留给实现者，原则是：侧栏出现时正文不能被挤窄。
- 底部抽屉 **［我的决定］**：系列文章有两个页签“本文目录”和“系列篇目”，非系列文章只有目录、不显示页签。点目录项后跳转并自动收起抽屉。点遮罩或按 Esc 关闭。
- 悬浮按钮只在“有东西被收起来”时出现：窄屏下有目录或系列时出现；中等宽度下只有系列文章才出现。
- 目录不显示的情况 **［我的决定］**：文章标题数少于 2 个，或 front matter 写了 `toc: false`。目录默认收录二、三级标题，可通过 Hugo 的 `markup.tableOfContents` 配置调整。
- 文章头部：标题、发布日期、更新日期（与发布日期不同才显示）、字数与预计阅读时间、标签。
- 文章尾部：系列文章显示本系列的上一篇/下一篇；非系列文章显示按时间的上一篇/下一篇。之后是评论（若开启）。

### 5.3 其他页面

- **首页**：可配置两种列表样式。默认“紧凑”：按年份分组，每篇一行，日期 + 标题。另一种“摘要”：标题、日期、标签加两三行摘要。两种都分页。首页顶部可选显示一段站点简介（来自首页内容文件）。
- **标签**：标签总览页（所有标签及文章数）和单个标签页（紧凑列表）。
- **归档**：按年份列出全部文章，不分页。
- **系列**：系列总览页（每个系列的名称、简介、篇数）和单个系列页（带序号的有序篇目）。
- **搜索**：见 5.6。
- **404**：简单提示加回首页链接。
- **页头**：左侧站点名；右侧是 `menus.main` 定义的导航、搜索入口（开启时）、明暗切换。窄屏下导航的收纳方式留给实现者。
- **页脚**：版权行、RSS 链接、可配置的一行自定义文字。

### 5.4 系列

- 用 Hugo 分类法实现，分类名 `series`。文章在 front matter 里写 `series: ["系列名"]`。**［我的决定］** 一篇文章只按它的第一个系列来展示。
- 系列内排序 **［我的决定］**：文章设置了 `weight` 就按 `weight` 升序，否则按日期升序。
- 系列简介来自 `content/series/<系列名>/_index.md`（可选）。

### 5.5 Markdown 渲染

正文是这个主题的核心，下列每一项都要有明确样式，并在 `exampleSite` 的样式测试文章中出现：

- **标题**：二到六级；鼠标悬停时显示锚点链接；跳转到锚点时不被页头或吸顶元素遮住。
- **段落与中文排版** **［我的决定］**：行高约 1.8；段间距大于行间距；左对齐不两端对齐；启用严格的中文断行规则；长英文单词和长链接可断行；在支持的浏览器里自动加中英文间距、压缩连续标点（渐进增强）。
- **列表**：有序、无序、多层嵌套、任务列表。
- **引用块**：左侧细线、次要文字色。
- **提示框**：用 GitHub 风格语法 `> [!NOTE]`，支持 NOTE、TIP、IMPORTANT、WARNING、CAUTION 五种，各有颜色与图标，支持自定义标题；类型名显示为界面语言对应的文字。
- **代码块**：语法高亮（明暗两套配色，用 CSS 类而非内联样式）；顶部一行显示语言名和复制按钮；超宽时块内横向滚动；支持行号和行高亮。行内代码有浅底色。
- **表格**：超宽时表格自己横向滚动；表头有区分；行间细线。
- **图片**：不超过正文宽度；`title` 文字作为图注；懒加载；点击放大查看，点击或按 Esc 关闭。
- **数学公式**：行内和块级；只在用到公式的页面加载相关资源；超宽的块级公式自己横向滚动。
- **Mermaid 图表**：用 ```` ```mermaid ```` 代码块书写；只在用到的页面加载；配色跟随明暗模式。
- **其他**：脚注、分隔线、`<kbd>`、`<mark>`、`<details>`、定义列表、外链。

### 5.6 搜索

- 配置开启后，页头出现搜索入口，点击或按 `/` 打开搜索弹窗 **［我的决定］**（用弹窗而不是单独页面，这样使用者不需要额外建内容文件）。
- Hugo 构建时在站点根输出一份 JSON 索引，含每篇文章的标题、链接、日期、标签和纯文本正文。
- 首次打开弹窗时才下载索引。匹配规则：不区分大小写，按空格拆成多个关键词，全部命中才算匹配；标题命中排在正文命中前面；结果显示标题、日期和带关键词高亮的正文片段。
- 搜索脚本是独立文件，除了索引地址不依赖主题其他脚本。

### 5.7 深色模式

- 默认跟随系统；页头按钮可手动切换，选择记在浏览器本地。
- 在页面最早期就确定主题，避免闪烁。
- 切换时代码高亮、Mermaid 图表、giscus 评论一起切换。

### 5.8 评论

- 支持 giscus，默认关闭，填入配置后开启。
- 滚动到评论区附近再加载。
- 单篇文章可用 `comments: false` 关闭。
- 验收范围 **［我的决定］**：目前没有可用于 giscus 的真实仓库，所以 `exampleSite` 里评论保持关闭，README 用占位参数。只验证“脚本按需注入、明暗切换时向评论框发出切换消息”，不做真实评论的端到端验证。使用者之后提供仓库参数即可补验。

### 5.9 配置与文字

- 界面文字提供简体中文和英文两套，随站点语言切换，默认中文。
- 站点必须自己写的配置 **［我的决定］**：因为第 3 节的合并限制，有一小段配置只能放在使用者的站点配置里。原则是模板里能绕开的都绕开（例如代码高亮用 CSS 类、搜索索引的生成），剩下绕不开的压到最少，并在 README 和 `exampleSite` 里给出可以整段复制的版本。预计包括：声明 `series` 分类法、站点语言设为中文、开启中文字数统计、公式定界符；可选项：允许正文内嵌原始 HTML（`<kbd>`、`<mark>`、`<details>` 需要）。缺少必需配置时，对应功能应安静地不出现，而不是构建报错。
- 主题自带 `params` 默认值；使用者在自己站点配置里覆盖。配置项清单（名称留给实现者，但须在 README 里逐项说明）：首页列表样式、是否显示字数/阅读时间、搜索开关、评论（giscus 参数）、公式开关与 CDN 地址、Mermaid CDN 地址、页脚自定义文字、外链是否新窗口打开。
- 单篇文章 front matter 可用：`toc`、`comments`、`series`、`weight`、`math`（如实现需要）、`description`。

### 5.10 仓库内容

- 主题本体：模板、样式、脚本、界面文字、默认配置、`theme.toml`、文章原型。
- `exampleSite/`：可直接运行的示例站点，内容至少包括：
  - 一篇“样式测试”文章，覆盖 5.5 的全部元素；
  - 一个三篇以上的系列；
  - 一篇长篇中文随笔；
  - 一篇图文；
  - 一篇含公式和 Mermaid 的技术文章；
  - 归档页、若干标签、导航菜单。
- `README.md`（中文为主）：截图、安装、配置项、front matter、如何覆盖样式、如何本地运行示例站点。
- `LICENSE`：MIT **［我的决定］**。

## 6. 验收标准

1. 用 Hugo 0.169.0 构建 `exampleSite`，无错误、无警告。
2. 在 375、768（均为窄屏布局）、1024（中等布局）、1440（大屏布局）四种宽度下，明、暗两种模式，逐页检查：首页（两种列表样式）、系列文章页、非系列文章页、样式测试文章、标签页、归档页、系列页、404。
3. 任何宽度下页面本身都没有横向滚动条。
4. 目录：宽屏高亮跟随滚动；窄屏悬浮按钮、抽屉、页签工作正常；点击目录项跳转位置正确、不被遮挡。
5. 搜索能搜到中文和英文关键词并高亮；代码复制可用；图片放大可用；明暗切换无闪烁，刷新后保持。
6. 禁用 JavaScript 后，文章仍可完整阅读，导航可用。
7. 公式、Mermaid、评论相关资源只出现在用到它们的页面上。

## 7. 留给实现者

- 目录结构、文件拆分、模板和 partial 的命名。
- 断点像素值、具体字号、间距刻度、颜色的最终取值（在 5.1 的方向内）。
- 语法高亮用哪两套 Chroma 配色（要求与素白风格协调）。
- 公式用构建时渲染还是浏览器端渲染；“只在用到的页面加载”的具体机制。
- 窄屏页头导航的收纳方式。
- 无 JavaScript 时目录的降级方式（例如文首折叠块）。
- 图标的实现方式（内联 SVG 等），数量保持最少。
- SEO 元信息、Open Graph、RSS 使用 Hugo 内置能力即可。
- `exampleSite` 引用主题的方式，以及 README 里对应的运行命令。
